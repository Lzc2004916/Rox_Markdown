# Rox-Markdown 前后端架构与联调分析

> 分析目标：`D:\Rox_Markdown`（前端 / 桌面客户端） × `D:\Rox_Markdown_backend`（后端鉴权服务）
> 分析时间：2026-10-23 ｜ 依据：源码实测，非推测

---

## 0. 一句话结论

**前端是一个 Electron + Vue3 的 Markdown 卡片编辑器（离线可用），后端是一个极薄的"激活码换 JWT + 付费主题鉴权"服务（6 个接口）。两者只有 3 条真实调用链路，耦合度低，前端在后端完全不可用时也能启动（降级为离线模式）。**

| 维度 | 前端 `Rox_Markdown` | 后端 `Rox_Markdown_backend` |
|---|---|---|
| 定位 | Markdown 编辑器 + 卡片渲染导出（PNG/JPG/PDF） | 激活码兑换 / VIP 权益校验 / exe 分发 |
| 语言 | TypeScript 5.7 | Java 17 |
| 核心框架 | Vue 3.5 + Vite 4.5 + Electron 35 | Spring Boot 3.2.12 |
| UI 方案 | Tailwind 3.4 + daisyUI 4.12 | 无（仅静态页） |
| 数据层 | localStorage（无数据库） | MySQL + MyBatis-Plus 3.5.5 |
| 鉴权 | 持有 JWT，存 localStorage | 签发/校验 JWT（HMAC256） |
| 端口 | dev 5173（Vite 默认）/ Electron 无端口 | **6060** |
| 仓库形态 | 单仓多端（Electron / iOS / Web） | 单模块 Maven |

**两端的关系是"卖主题"**：前端内置 48 个付费卡片主题，未激活只能看不能选；后端负责把激活码换成 JWT，并在切主题时二次校验权益。

**调用关系（一条典型请求的穿透路径）**

```
HTTP ──▶ CorsConfig(WebMvcConfigurer)
      ──▶ SecurityFilterChain
            ├─ JwtAuthFilter（OncePerRequestFilter，先于 UsernamePasswordAuthenticationFilter）
            │     解析 Authorization → JWT.verify → new LoginUser → SecurityContextHolder
            ├─ authorizeHttpRequests（白名单 permitAll / 其余 authenticated）
            └─ 拒绝时走 Spring 默认 403
      ──▶ Controller（@Valid 入参校验）
      ──▶ @RequireVip 切面（仅 /api/theme/access）→ 读 SecurityContext → 查库判权益
      ──▶ Service（业务 + 抛 BusinessException）
      ──▶ Mapper（MyBatis-Plus BaseMapper / @Update）
      ──▶ MySQL(redeem_token)
      ──▶ Result<T> 统一包装
      ──▶ GlobalExceptionHandler（异常 → Result JSON）
```

## 3. 前后端联调（核心）

### 3.1 后端对外接口全清单（实测 6 个，无遗漏）

| # | 方法 | 路径 | 鉴权 | 白名单 | 入参 | 出参 `data` |
|---|---|---|---|---|---|---|
| 1 | POST | `/api/auth/login` | 匿名 | ✅ permitAll | Body `{token: string}` | `{token, type, expireAtMs}` |
| 2 | GET | `/api/auth/status` | **Bearer JWT** | ❌ 需登录 | Header `Authorization` | `{token, type, expireAtMs}` |
| 3 | GET | `/api/theme/access` | Bearer + **@RequireVip** | ❌ 需登录 | Query `?themeId=xxx` | `{allowed: true, themeId}` |
| 4 | GET | `/api/theme/public` | 匿名（内部软校验） | ✅ permitAll | Header 可选 | `{allPaidThemes[], allowedPaidThemes[]}` |
| 5 | GET | `/api/app/info` | 匿名 | ✅ `/api/app/**` | 无 | `{version, updateDate, downloadUrl, minSystem}` |
| 6 | GET | `/api/app/download` | 匿名 | ✅ `/api/app/**` | 无 | **二进制流**（exe），非 Result |

**统一响应体**（除 6 号）

```json
{ "code": "200", "msg": "ok", "data": { }, "success": true }
```

错误码（`ResultCode`）：

| code | 常量 | msg | 触发点 |
|---|---|---|---|
| `200` | — | `ok` | `Result.success()` 写死 "200"（枚举里 SUCCESS 是 0，不一致） |
| `-1` | — | 自定义 | `Result.error(msg)` 默认 |
| `400` | PARAM_ERROR | 参数错误 | `@Valid` 校验失败 |
| `401` | UNAUTHORIZED | 未登录或登录已过期 | 切面拿不到 LoginUser |
| `403` | FORBIDDEN | 无权限 / **`VIP_已过期`** | `VipAspect` 判权益失败 |
| `1001` | TOKEN_INVALID | 激活码无效 | 码不存在 |
| `1002` | TOKEN_USED | 激活码已被使用 | 并发/重复兑换（`tryRedeem` 返回 0 且记录存在） |
| `1003` | TOKEN_EXPIRED | 激活码已过期 | **代码中从未抛出**（死枚举） |
| `500` | SERVER_ERROR | 服务器内部错误 | 兜底 `Exception` |

**鉴权机制细节**

- 算法：`HMAC256(secret)`，`issuer = rox-markdown` 强校验
- Claims：`sub` = `redeem_token.id`、`type` = WEEK/MONTH/LIFETIME、`expAt` = 权益到期毫秒戳（永久=0）、`iat`；**仅当 `expAtMs > 0` 才 `withExpiresAt`** → LIFETIME 的 JWT 永不过期
- 传递方式：`Authorization: Bearer <jwt>`，无 Cookie、无 Session（`STATELESS`）
- 三层校验：① Filter 验签 → ② `authenticated()` 拦截 → ③ `@RequireVip` 查库验权益
- `VipAspect` 放行逻辑：`themeId` 不在 `rox.paid-themes` 白名单内 → 免费主题直接放行；否则 `checkActive(redeemTokenId)` 查 `status=USED` 且未过期

### 3.4 三条完整调用链路（数据流）

#### 链路 A：启动时初始化会员态

```
main.ts → initPlatform() → createApp → App.vue onMounted()
  → auth.initFromStorage()
      ├─ GET /api/theme/public
      │     Controller: ThemeController.publicThemes()
      │       → ThemeService.isVip(request)      // 手动解 JWT + checkActive
      │       → Result.success({allPaidThemes, allowedPaidThemes})
      │     前端: paidThemes = allPaidThemes；失败 → 降级读 rox_paid_themes 缓存，offline=true
      └─ if (token) GET /api/auth/status
            前端拦截器加 Bearer → JwtAuthFilter 验签 → SecurityContext
            → AuthController.status() → RedeemTokenServiceImpl.status(jwt)
                USED+LIFETIME → {type:'LIFETIME', expireAtMs:0}
                USED 且过期   → {type:'EXPIRED', expireAtMs:0}
                USED 未过期   → {type:'WEEK'|'MONTH', expireAtMs}
            → 前端 vipType/expireAtMs → scheduleExpiry() 定时器 → 3 天内弹一次续费提醒
  → 遍历 documents：主题不可用或付费且非 VIP → 重置为 free 主题 `warm-editor`
```

#### 链路 B：点选付费主题（核心鉴权）

```
用户点 ThemeSelector 里的付费主题
  → App.vue selectTheme(newThemeId)
      ① 非付费主题 → 直接切，不发请求
      ② offline=true → 用本地缓存的 expireAtMs 判断，不发请求
      ③ 在线 → await checkThemeAccess(id)
            GET /api/theme/access?themeId=xxx  (Authorization: Bearer)
            → JwtAuthFilter 验签 → SecurityContext.setAuthentication(LoginUser)
            → VipAspect.@Before
                 principal 非 LoginUser → BusinessException(401)
                 themeId ∉ paid-themes → 免费放行
                 checkActive(id)=false → BusinessException(403, "VIP_已过期")
            → Controller 返回 Result.success({allowed:true, themeId})
            → 前端拦截器解包 → store.updateTheme() + applyThemePreset()
      ④ 抛错分支（catch）→ auth.markExpired() → 切回 warm-editor → 500ms 后弹 ActivationDialog
```

#### 链路 C：激活码兑换

```
ActivationDialog.onSubmit()
  → auth.activate(rawToken.trim().toUpperCase())
      → POST /api/auth/login  body:{token:"WEEK-XXXX"}
          Controller: AuthController.login(@Valid LoginReq)
          → RedeemTokenServiceImpl.redeem(token)
               token 空 → BusinessException(TOKEN_INVALID=1001)
               mapper.tryRedeem(token)  ← UPDATE ... SET status='USED',used_at=NOW()
                                            WHERE token=? AND status='UNUSED'  （乐观 CAS，防并发）
               updated=0 → 查记录：不存在→1001；存在→1002 TOKEN_USED
               updated=1 → 查全量记录 → WEEK: expireAt=now+7d / MONTH: now+30d → updateById
                        → expAtMs = expireAt.toInstant(+08:00).toEpochMilli()
                        → jwtUtil.issue(id, type, expAtMs)
          → Result.success({token: JWT, type, expireAtMs})
      → setToken(jwt) 写 localStorage.rox_token
      → 立即 initFromStorage()（再打一次 /theme/public + /auth/status 刷新状态）
  → emit('success') → App.onActivateSuccess()（若 pendingTheme 有值则自动切主题）
```

> **补充链路 D（下载分发，不经过前端 axios）**：
> `DownloadPage.vue:45` 把 `VITE_API_BASE` 去掉 `/api` 后缀 → `window.open(http://localhost:6060/download.html)` → 后端 `static/download.html` 内联脚本 `location.href='/api/app/download'` → `AppController.download()` 用 `FileSystemResource` 流式返回 `rox.exe.path` 指向的 exe。

| 后端情况 | HTTP | 响应体 | 前端拦截器分支 | 用户可见结果 |
|---|---|---|---|---|

### 3.6 跨域 / 代理 / 地址切换

| 场景 | 前端地址 | baseURL | 是否跨域 | 解决方案 |
|---|---|---|---|---|
| 开发（浏览器/Electron dev） | `http://localhost:5173` | `/api` | 否（同源） | Vite `server.proxy` → `http://localhost:6060`，`changeOrigin:true` |
| Electron 打包版 | `file://`（`win.loadFile(dist/index.html)`） | `http://localhost:6060/api` | **是** | 后端 `CorsConfig`：`allowedOriginPatterns("*")` + `allowCredentials(true)` + `maxAge:3600` |
| Web/移动端由后端托管 | `http://host/` | `/api`（需重构建） | 否 | 后端 `static/` 内置构建产物 + Security 白名单放行 `/`、`/assets/**` |
| iOS（Capacitor） | `capacitor://localhost` 或 bundled | 同上 | 是 | 同上 CORS |

**地址切换唯一开关**：`.env.development` / `.env.production` 里的 `VITE_API_BASE`。Vite 按 `mode` 自动加载，代码里没有硬编码 host（除 `backend/static/download.html` 与 `AppController` 的 exe 路径）。

**CORS 注意点**：`allowedOriginPatterns("*")` 与 `allowCredentials(true)` 组合在 Spring 中是合法的（不是 `allowedOrigins("*")`），能支持 Electron 的 `Origin: null`。生产环境建议收紧为具体域名。

## 5. 关键设计取舍（值得知道的 3 点）

1. **激活码即账号**：没有用户表、没有注册登录，`redeem_token` 一行既是凭证也是身份，JWT 的 `sub` 就是这行主键。好处是零注册成本、卖给微信客户直接发码；代价是无法换设备迁移、无法退款重置。
2. **前端强依赖但可降级**：会员态的"真值"在后端，但 `auth` store 完整实现了一套离线兜底（加密缓存 + 本地到期时间 + `offline` 标记），后端挂了免费功能全可用，只有付费主题锁死。这是桌面软件的正确取舍。
3. **每次切主题都打后端**：`selectTheme()` 不信任本地 `isVip`，在线时必调 `/api/theme/access`，防止用户改本地缓存白嫖。代价是切主题有 1 次 RTT 延迟。

## 6. 发现的问题与风险（按严重度）

### ① P0 级：JWT 密钥有明文兜底，泄露即可伪造任意会员

`application.yml:39` 的 `JWT_SECRET` 默认值是仓库内明文 64 位字符串。只要没设环境变量，任何人都能用它签出 `type=LIFETIME` 的 token，直接白嫖全部 48 个主题。**部署前必须设置 `JWT_SECRET` 环境变量，并把该默认值从 yml 中删除**（改成无默认值，启动即失败更安全）。

### ② P1 级：前后端存在未对齐的"幽灵接口"

- `src/api/theme.ts:19` 的 `getMyTheme()` 请求 `GET /api/theme/my`，**后端 `ThemeController` 无此映射**（`grep` 确认）；虽然当前无调用者，但一旦有人用就 403/404。
- `getPublicThemes()` 声明返回 `{paidThemes}`，后端实际返回 `{allPaidThemes, allowedPaidThemes}`。字段名不一致，且同样无调用者。
- `README.md` 写的 `sql/init.sql`、`runner/TokenGeneratorRunner` 在仓库中都不存在（实际是 `utils/TokenGenTool`）。

**建议**：删掉 `theme.ts` 里两个死函数，或补齐后端 `/api/theme/my`。

### ③ P1 级：VIP 错误提示链路断在"HTTP 200 里的 403"

`VipAspect` 抛的是 `BusinessException(403, "VIP_已过期")`，`GlobalExceptionHandler.handleBusiness()` 返回的是 **HTTP 200** + `code:"403"`。而 `request.ts` 的 `isVipError` 判断条件是 `msg === 'VIP_EXPIRED' || msg.includes('需开通会员') || status === 403` —— 三条全不命中（`msg` 是 `"VIP_已过期"`，`status` 是 200）。

结果：用户看到的是生硬的 `VIP_已过期`，而不是设计好的"会员已过期，已为你切换回免费主题"；且 `dispatchEvent('vip-expired')` 不会触发。

**修法**：把切面抛的 msg 改成 `VIP_EXPIRED`，或在前端 `isVipError` 里加 `res.code === '403'` 判断。

### ④ P1 级：`vip-expired` 事件无监听者，`pendingTheme` 从未赋值

- `request.ts:58` 派发 `vip-expired`，但全项目 `addEventListener('vip-expired')` **0 处**。注释里说"App.vue 里切回免费主题弹激活窗"，实际没实现（真正生效的是 `selectTheme` 的 catch 分支）。
- `auth.pendingTheme` 只在 `auth.ts` 和 `App.vue:820` 被**读**，从未被**写**。`ThemeSelector` 只 `emit('need-activate')`，没记录用户想点的主题。
- 后果：用户激活成功后，**必须重新点一次刚才想要的付费主题**，`onActivateSuccess()` 的自动切换是死代码。

**修法**：`App.vue` 的 `selectTheme` 在弹窗前写 `auth.pendingTheme = newThemeId`。

### ⑤ P2 级：未登录被误报成"会员已过期"

`SecurityConfig` 没有配 `authenticationEntryPoint`，未携带/携带过期 JWT 访问受保护接口时，Spring 返回**默认 403**（无 `Result` 结构）。前端把所有 403 都当 VIP 失效处理 → 提示"会员已过期，已为你切换回免费主题"。语义错误，易误导。

顺带：`/api/auth/status` 未加入 `permitAll`，导致 `AuthController.status()` 里那段"无 token 返回 FREE"的优雅降级**永远走不到**（请求在 Filter 链就被 403 拦掉）。WEEK 卡 JWT 过期后，客户端只能靠 `catch` 进 offline 模式，而非走该分支。

**修法**：`/api/auth/status` 加入 `permitAll`，并配置统一的 401/403 `Result` 响应体。

### ⑥ P2 级：`.env.production` 指向 localhost，与"后端托管前端"的部署方式冲突

`.env.production` 是 `VITE_API_BASE=http://localhost:6060/api`。但后端 `static/` 里放的正是一份前端构建产物 —— 部署到服务器后，用户的浏览器会去请求**自己电脑的** `localhost:6060`，必然失败。

**修法**：托管到服务器时用 `VITE_API_BASE=/api` 重新构建；或用 `.env.staging` 区分"桌面打包版（localhost）"与"Web 托管版（相对路径）"。

### ⑦ P2 级：激活码枚举与信息泄露

`tryRedeem` 返回 0 后，代码区分了 `TOKEN_INVALID(1001)` 和 `TOKEN_USED(1002)` —— 攻击者可据此判断"某个码是否真实存在"，配合无任何限流的 `/api/auth/login`，可批量探测。`TokenGenTool` 用 12 位随机大写串（`WEEK-XXXXXXXXXXXX`），熵足够，但**接口无频率限制**这一点仍是隐患。

**修法**：登录接口加 IP/设备维度限流（如 1 分钟 10 次），或把 1001/1002 统一为"激活码无效"。

### ⑧ P3 级：零散问题

| 问题 | 位置 | 说明 |
|---|---|---|
| `TOKEN_EXPIRED(1003)` 从未抛出 | `ResultCode` | README 描述"WEEK 码已过期 → TOKEN_EXPIRED"，实际已 USED 的码重兑返回的是 `TOKEN_USED` |
| `ResultCode.SUCCESS=0` vs `Result.success()` 填 `"200"` | `Result.java` | 枚举值形同虚设，前端两套判断都兼容所以没炸 |
| 时区硬编码 `ZoneOffset.of("+8")` | `RedeemTokenServiceImpl` | 服务器 TZ 非东八区时会算错 `expAtMs` |
| `TokenGenTool` 硬编码 `root/root` | `utils/TokenGenTool.java:19-21` | 与 yml 环境变量体系脱节，改密码后工具失效 |
| `rox.app.*` 未在 yml 中定义 | `AppController` | 版本号只能改 Java 代码 |
| `MyBatisPlusConfig` 分页插件无使用处 | `config` | 当前无分页查询，冗余但无害 |
| `getMyTheme`/`getPublicThemes` 死代码 | `src/api/theme.ts` | 见 ② |
| 生产构建 `drop console` | `vite.config.ts` | 打包版无任何日志，线上排障困难 |
| `CorsConfig` 全放开 + `allowCredentials(true)` | `config/CorsConfig.java` | 任意站点可携带凭证请求，生产应收紧 |
| 激活后 `initFromStorage` 触发 2 次请求 | `stores/auth.ts:120` | `/theme/public` 与 `/auth/status` 各再打一次，无缓存策略 |

## 7. 附录：接口快速验证命令

```bash
# 1. 公开接口（应返回 48 个主题）
curl -s http://localhost:6060/api/theme/public

# 2. 版本信息
curl -s http://localhost:6060/api/app/info

# 3. 兑换（把 WEEK-xxx 换成 TokenGenTool 生成的码）
curl -s -X POST http://localhost:6060/api/auth/login \
     -H "Content-Type: application/json" \
     -d '{"token":"WEEK-A8K2M9P3Q7X1"}'
# → {"code":"200","data":{"token":"eyJ...","type":"WEEK","expireAtMs":1761...}}

# 4. 查状态（Bearer 上一步的 token）
curl -s http://localhost:6060/api/auth/status -H "Authorization: Bearer eyJ..."

# 5. 付费主题鉴权（VIP 时应 allowed:true）
curl -s "http://localhost:6060/api/theme/access?themeId=cyber-neon" \
     -H "Authorization: Bearer eyJ..."

# 6. 免费主题 v.s. 未登录 → 应 403（当前会被前端误读为会员过期）
curl -s -o /dev/null -w "%{http_code}\n" \
     "http://localhost:6060/api/theme/access?themeId=cyber-neon"
```
